# 5. Complexity and memory (сложность и память)

## Зачем оценивать алгоритм

Два решения могут выдавать одинаковый ответ, но одно перестанет работать на больших входах. Мы оцениваем, как растут время и дополнительная память при размере входа `n`.

`O(...)` описывает верхнюю асимптотическую границу, отбрасывая константы и младшие слагаемые:

| Сложность | Пример |
|---|---|
| `O(1)` | `v[5]`, `stack.top()` |
| `O(log n)` | двоичный поиск |
| `O(n)` | один проход по массиву |
| `O(n log n)` | эффективные сортировки |
| `O(n²)` | два вложенных прохода |
| `O(2^n)` | полный перебор подмножеств |

## Как считать

Считай повторения основной операции. Последовательные участки складываются: `O(n) + O(n²) = O(n²)`. Вложенные независимые циклы перемножаются.

```cpp
for (int i = 0; i < n; ++i) {       // n раз
    for (int j = 0; j < n; ++j) {   // n раз для каждого i
        work();                     // всего n² => O(n²)
    }
}
```

Если внутренний индекс каждый раз удваивается, это `O(log n)`:

```cpp
for (int x = 1; x < n; x *= 2) { /* ... */ }
```

## Память

Разделяй:

- память входных данных — то, что уже дано алгоритму;
- дополнительную память — новые массивы, контейнеры, рекурсионный стек.

Например, сортировка копированием массива использует `O(n)` дополнительной памяти, а два указателя — `O(1)`. Рекурсивная функция глубины `n` может занимать `O(n)` на стеке вызовов.

## Амортизированная сложность

`vector.push_back` иногда расширяет массив и копирует `n` элементов (`O(n)` для одной операции), но за последовательность `n` вставок суммарная стоимость `O(n)`, то есть амортизированно `O(1)` на вставку.

## Практическая оценка

Всегда указывай обе характеристики: «`O(n log n)` времени, `O(n)` дополнительной памяти». Для ограничения памяти важны не только массивы, но и узлы списков, рекурсия и накладные расходы контейнера.
